# Neuropixels Explorer architecture

[Documentation index](../README.md) · [IA](IA.md) · [Data contract](DATA_CONTRACT.md)

This document owns runtime and module boundaries. Product requirements live in
PRD, user-facing surfaces in IA, and capability preservation in the parity matrix.

## Presentation ownership

`workspace-presentation.css` owns the observation-bench visual system, including
local font stacks, theme surfaces, responsive layout and shared control sizes.
`app.js` moves the existing mini Probe into `#probe-dock` and groups video tools
without creating duplicate controllers. The dock, video layout and playback
details change presentation only; neural/video selection stays in shared state.
Both interval position/rate plots and the template renderer remain intact.

## Runtime model

The portable `index.html` and the identical staging mirror `dist/Neuropixels-Explorer.html` are generated by
`scripts/build-standalone.cjs`. Ordinary and explicit-path builds stay in staging; only `--promote` updates tracked `index.html`. The build applies pinned JavaScript compression without property mangling, preserves identifiers in modules that serialize Worker factories, gzip-packs the NWB worker, and hashes each resulting inline script for the page's Content Security Policy.
The first NWB import checks the compressed HDF5 reader against the SHA-256 in its loader before starting a worker.
The portable page permits local media, local workers and WebAssembly. Connections from it are restricted to its own origin and local blob/data URLs.
`browser-project-ui.js` connects the shared workspace to local file selection and
`browser-storage.js` tab-local working copies. Existing IndexedDB projects can be opened for editing. `browser-nwb-worker.js` uses WORKERFS
random access to an NWB 2.x HDF5 file. It reads the Units table and merges the selected Unit
spike trains into float64 sample-equivalent values without rounding. Original Unit
IDs and available electrode assignments are retained; templates are not synthesized.
Dropped video is held by Blob reference. An explicit package export writes the workspace to disk. The page needs no Python API or CDN.
It has no service worker; the saved HTML is the offline application entry.

The developer service is available to maintain existing indexed catalogs. At `/` and `/index.html` it serves the shared template `scripts/explorer-shell.html`, which loads
plain JavaScript/CSS. The build injects the browser project adapter only into the
standalone file; analysis, annotations and Probe renderers remain shared.

Large arrays are loaded lazily for the active Recording. Unit analysis runs in
a Web Worker when available and falls back to the main thread with an explicit
status indication.

The signal plot retains timestamped spike windows while panning and reuses the
overlap in the new view. Local time-sorted files can supply neighboring Units in
one short read. Database recordings prefetch nearby rows because fetching a new
Unit there loads its train. A pending read can update the display during a
gesture. Missing time stays distinguishable from an observed interval with zero spikes.

An optional indexed mode uses the reusable local service in `server/`. The
service implementation and schema migrations are release source. Its generated
SQLite database, research data, analysis outputs, logs, and runtime paths stay
outside the repository and are not required by the standalone folder workflow.

## Module map

Implementation must retain the plain-browser architecture, existing theme tokens
and styling conventions unless a separately scoped architecture change is requested.
Before workspace changes, trace the entry point, shared state, Unit and Probe views,
spike/metadata sources, video mapping, and relevant tests in the actual checkout.
Screenshots describe an observed state; they do not establish the target architecture.

Display preprocessing runs outside paint and interaction hot paths. Do not rescan
all spikes on each paint or interaction. Reuse prepared summaries for the active
recording, keep long work off the UI thread, and preserve exact source mappings.
Summary semantics and cache identity belong to [Data Contract](DATA_CONTRACT.md);
the early checkpoint's deferral of persistent caching is not a current restriction.

- `scripts/explorer-shell.html` defines the Explorer interface; `VERSION` controls its release label.
- `scripts/app.js` owns application state, folder selection, review modes, and
  DOM coordination.
- `scripts/activity-overview.js` renders the unified activity/anatomy canvas,
  anatomical groups, local Unit expansion and shared-time interaction intents.
  Display summaries are prepared outside paint paths; their definitions belong
  to the [data contract](DATA_CONTRACT.md).
- `scripts/pinned-comparison.js` retains up to six loaded Unit results from the
  current Recording independently of temporary activity focus. It reuses
  `PlotManager` in raster-only mode and synchronizes windows/cursors through
  the application's experiment view. Recording changes destroy retained plots.
- `scripts/kilosort-core.js` indexes KiloSort files, parses NPY arrays, and
  computes Unit-level review data.
- `scripts/template-footprint.js` renders per-channel stored template amplitudes,
  measured channel positions and a selectable common-scale waveform. The payload
  comes from the folder worker's `buildTemplateFootprint` or the service's
  `template_footprint.py`, through the existing Unit review response. It has no
  independent time selection, network requests or writes to source data.
  `mini-probe.js` keeps its expansion and channel selection independent of interval
  statistics; `app.js` supplies only the review matching the current selected Unit.
- `scripts/region-core.js` validates and joins Unit- and depth-level
  brain-region metadata without inferring missing anatomy.
- `scripts/data-status.js` classifies core, optional, invalid, and future data
  capabilities for the compact status surface.
- `scripts/theme.js` owns the persisted theme preference and the shared UI,
  signal-Canvas, Probe, and Unit color palettes.
- `scripts/i18n.js` owns the persisted language preference, the English,
  Simplified Chinese, and Spanish dictionaries, and the professional
  terminology glossary. File names, brain-region abbreviations, and KiloSort
  field names are deliberately outside translation.
- `docs/guides/USER_GUIDE.*.md` are the editable Help sources.
  `scripts/build-help-content.cjs` precompiles them into the checked-in
  `scripts/help-content.js` asset, keeping the Help drawer compatible with
  direct `file://` use and independent of online Markdown services.
- `scripts/plots.js` renders signals and linked time-window interactions.
- `scripts/video-sync.js` owns `VideoStream` playback, invertible `TimeMapping`,
  deterministic validation frames, transport controls, and the shared neural
  playhead. A local video file and a generated synthetic source use the same
  controller. Optional measured frame-clock anchors are stored under
  `TimeMapping.provenance.frame_clock`; both playback and CSV export use the
  same piecewise mapping and reject extrapolation beyond measured coverage.
- `scripts/stream-contracts.js` exposes the versioned Raw Voltage provider
  registry. A future provider must advertise supported `raw_voltage`, `ap`, or
  `lfp` streams and return a reader with `readWindow(request)` and `close()`;
  this release intentionally registers no provider.
- `scripts/probe-view.js` renders physical Probe groups, Unit locations, and
  optional atlas-colored depth segments.
- `scripts/database-client.js` adapts the optional local-service API to the
  same Explorer state model.
- `server/neuropixels_explorer/` provides the catalog API, transactional
  incremental ingest, lazy NPY access, bounded in-memory caches, safe runtime
  path resolution, migration validation, and the CLI.
- `database/migrations/` is the canonical ordered SQLite schema history.
- `styles/app.css` contains the current application layout and visual system.
- `tests/validate-real-data.cjs` provides portable code checks and an optional
  local real-data integration path.
- `tests/validate-i18n-help.cjs` validates dictionary coverage, glossary terms,
  local Help parity, contextual explanations, and keyboard-accessibility
  contracts.
- `tests/validate-video-sync.cjs` validates time-mapping round trips,
  deterministic frames, shared-view wiring, and the Raw Voltage extension
  contract.
- `tests/python/` validates migrations, the frontend/API response contract,
  lazy file access, path containment, and repository exclusions using only
  generated synthetic fixtures.

## Data boundary

KiloSort is the source for spikes, amplitudes, templates, positions, and Probe
geometry. Brain-region labels are a separate optional input. Missing anatomy is
reported as unavailable rather than inferred. A depth-level mapping is not a
registered three-dimensional atlas trajectory.

SQLite is a metadata catalog, not a large-payload store. Asset rows use paths
relative to a runtime `--data-root`. The service resolves and contains each
path under that root, memory-maps active NPY arrays, and keeps only bounded
Recording and Unit caches. Video remains an external asset with explicit
stream and synchronization metadata; the local service exposes it through
path-contained HTTP range requests. Raw voltage remains an external future
asset behind the provider contract and is not read or rendered in this release.

Incremental ingest uses a two-phase boundary. Selected files first stream to a
session-specific staging directory while role, Recording identity, checksum,
NPY shape, and conflict rules are validated. Commit then uses one SQLite
transaction and atomic file moves into `managed-assets/`; an exception rolls
back the database and moves every file back to staging. Only changed
Recordings have their bounded array and Unit caches invalidated. The browser
refreshes those Recording snapshots in place so open Units, time windows,
history, and panel layout remain unchanged.

## Repository boundary

The release source includes the UI, reusable service, migrations, API adapter,
documentation, and portable tests. It excludes private experiment data,
generated SQLite files and sidecars, analysis reports and artifacts, logs,
secrets, and machine-specific absolute paths. `.gitignore` prevents ordinary
accidental additions, while `tests/python/test_repository_boundary.py` checks
the tracked tree and expected ignore behavior.

Research-specific import adapters may remain next to protected source data.
They may not redefine the product schema: a populated catalog must be created
from the checked-in migrations and pass `validate-db` before the Explorer opens
it. This keeps acquisition-specific knowledge outside the product without
allowing the frontend and database contract to drift.

## Versioning policy

`main` contains one current application tree. Releases are represented by Git
tags and release notes in `CHANGELOG.md`; full `vX.Y.Z/` snapshot directories
are not added to the current tree. Previous layouts remain recoverable from Git
history. Starting with v3.3, a product tag also identifies the Python service
version and the highest checked-in SQLite migration.


## Behavior annotation beta

The separately authorized annotation round adds `scripts/annotation-core.js`
(immutable project operations and validation), `scripts/annotation-ui.js`
(IndexedDB drafts, group/clip review, local video sampling and shared-state
integration), and `scripts/behavior-discovery.js` (an experimental motion
baseline executed in a worker). The app still owns the only neural cursor and
visible time range. Video-relative annotation boundaries are projected through
its existing time mapping. Annotation imports do not modify the neural catalog.

Raw candidate runs, editable intervals, laboratory schemes and review states
are distinct. Exported project JSON includes all schemes and original runs;
CSV uses the current scheme and records the current synchronization mapping.
External algorithms use a versioned candidate-file contract rather than adding
their training stacks to the browser. See `docs/contracts/BEHAVIOR_ANNOTATION.md` for exact
semantics, limits, reproducible trials and source/license boundaries.

## Allen adapter boundary

The optional scripts in `scripts/*allen*.py` download an explicit public file
manifest, validate camera clocks, adapt one physical NWB probe per Recording,
and run bounded analysis examples. They write generated arrays/catalogs and
provenance beside external source data; schema version 3 is unchanged. Original
Allen unit IDs, labels, probe identities, spike seconds and peak-channel anatomy
are retained. The derived float64 sample-equivalent arrays serve the existing
KiloSort reader contract and do not represent another spike-sorting run.
See `docs/validation/ALLEN_VBN_VALIDATION.md` for acquisition-specific limits and commands.

## Local projects and compact annotation (Beta 3)

`project-ui.js` owns the empty-workspace SVG illustrations, top project toolbar,
project menu and local project actions. `local_projects.py` opens a native picker in a separate process and
returns opaque candidate/file IDs. A browser request cannot nominate an arbitrary
source path. The service registers selected Kilosort/video files in place using
fingerprinted grants; NWB imports reuse the Allen physical-probe adapter and
write derived arrays under `.explorer-imports`. Source grants and recent project
links live in `.explorer-local.json` under the configured runtime data root.
These machine-local files, original data and generated arrays stay outside Git.
The local mutation endpoints reject foreign origins and non-loopback hosts.

`mini-probe.js` renders available Unit coordinates and links Unit/region selection
to the existing experiment state. It depicts measured positions, not an inferred
atlas trajectory. Missing depth is not zero. Activity and unit-review responses
use original catalog peak-channel coordinates when present and available
Kilosort geometry otherwise. The server display-cache version is incremented so
older cached coordinates cannot silently survive the adapter fix.

Interval distribution reuses exact half-open counts from `interval_activity.py`.
`mini-probe.js` shares one result between point radii, a depth/rate stem plot and
the complete Unit list. Orientation and Unit selection reuse the current result;
new Recording/interval requests abort and discard stale responses. The activity
canvas's accessible behavior strip uses the annotation controller's existing
mapped selection with `openEditor: false`; it does not save or relabel segments.

The annotation panel now lives in the video body. The time strip supports direct
interval selection; batch review moves the same controller into a native dialog.
Video enlargement and annotation use the existing experiment split. `app.js`
owns the two emphasis requests and independent normal/focused proportions for
side-by-side and video-above layouts. The video control workbench scrolls separately
from the media stage; CSS presentation lives in `workspace-presentation.css`.
Layout switches reorder the same DOM regions without changing experiment data or selection.
Annotation UI owns editor visibility and reports it through `onOpenChange`.
Layout changes do not mutate scientific selection, time mapping or datasets.
Annotation JSON schemas and candidate provenance are unchanged. Service projects
use project-scoped draft storage through the annotation controller store interface;
folder mode retains browser IndexedDB. `project_files.py` serializes catalog metadata,
fingerprinted source references, video mappings and complete annotation documents
to `.neuroproject.json`. Opening it restores a fresh catalog transactionally and
re-registers file grants. `project_checks.py` reports capability-specific input checks.
The UI flushes annotation writes before saving or switching projects; file save is
atomic and separate from local draft autosave. Only the native picker selects paths.

## Event response checkpoint

`event-analysis-core.js` is a pure event/annotation adapter and numerical kernel. `event-analysis-ui.js` adds the event analysis tabs inside the neural pane and shared-source return. A dedicated disposable Worker generated by `kilosort-core.js` reads selected Unit trains in bounded paired NPY chunks; it does not replace or cancel the activity Worker. event-analysis-storage.js owns bounded fingerprinting, binary serialization and restore validation. BrowserProjectUI/ProjectStore atomically save the optional result asset independently of annotation writes; existing project and IndexedDB schemas are unchanged. Core responseSummary and splitHalfStability supply exact group means and bounded diagnostic runs; Clustering and split-half fits remain in the disposable event Worker; UI summaries are derived from retained rates. The UI limits heatmap pixel blocks without altering source arrays or the main anatomical ordering. See [Event responses](contracts/EVENT_RESPONSES.md).

`video-features.js` owns bounded data-only model exchange, keypoint transforms, seeded grouping and disposable Worker source. `annotation-ui.js` connects it to existing review/undo/persistence. `video-sync.js` retains a local Blob reference only for file/browser-project video identity checks and clears it on source release. No remote inference/plugin runtime is installed. See [Video feature contract](contracts/VIDEO_FEATURES.md).

`ProjectUI.linkedVideoFingerprint` supplies a scoped callback for selected same-origin service media. `LocalProjects.video_fingerprint` binds the request to an existing project/recording/video grant, and `video_fingerprint.py` performs bounded, uncached ordered-chunk hashing with file-change checks. One nonblocking hash lock bounds service I/O; no media payload, new grant, remote model or direct filesystem path crosses the API. Local Blob handling remains independent.

The optional `video-model-adapter.js` supplies independent Blob-backed video decoding and a trusted source-integrated model callback. `AnnotationController.runVideoModel` uses the same validated feature Worker, review and save path; it guards source, annotation and mapping changes. Input snapshots and model provenance are preserved. No arbitrary script loader or remote runtime is added. See the local adapter section of [Video features](contracts/VIDEO_FEATURES.md).

## Continuous population dynamics modules

`population-dynamics-core.js` owns deterministic counts, train-only PCA and held-out model comparison. `kilosort-core.js` supplies its disposable Worker and optional range-limited retained spike reader without changing event-reader defaults. `population-dynamics-ui.js` owns the on-demand dialog and delegates source return to the main shared view. `population-dynamics-storage.js` validates and serializes a separate optional analysis asset; BrowserProjectUI and ProjectStore replace only its matching role/Recording. No runtime dependency, server or model download is required. See [contract](contracts/POPULATION_DYNAMICS.md).
